## Its own sandbox

Each agent runs in its own gVisor container with a read-only system and its own network. It can't reach another agent, your server or your LAN.

## A firewall

Agents can make HTTPS calls out, and nothing else. Private ranges and the cloud metadata address are blocked. If the firewall can't be applied, every agent stops.

## OpenHut holds the keys

Agents reach your data only through OpenHut's gateway. It keeps every password encrypted, checks each call against what you allowed, and logs it.

## What it doesn't cover

A tricked agent can still leak what it holds itself: its Slack, WhatsApp or Telegram credentials, its memories and the shared Claude token.

## What OpenHut sends us

Your server sends a few anonymous usage events to openhut.dev, so we can see how OpenHut is used and fix what's missing:

- That setup finished, and once a day that the server is running, with its version and rough size (for example "2–5 agents").
- When an agent, channel or connection is added or removed, with only its kind (for example "slack" or "postgres").
- When someone is invited or joins, with only their role, and when a skill or memory is edited.
- Which dashboard pages are opened, by page name.
- That a person sent one of your agents a message: the agent's name and the channel (Slack, WhatsApp, Telegram or the dashboard). Never who sent it or what it says.
- The owner's email, so we know whose server it is.

It never sends anyone else's email, people's names, what messages say, skills, memories, passwords or connection details. Each server is counted by a random ID.

An owner or admin can turn it off, or back on, in **Admin › Usage data**. Turning it off also drops anything not sent yet.
