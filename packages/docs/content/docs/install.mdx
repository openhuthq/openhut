## What you need

- A Linux server or VM. Any distribution, x86_64 or arm64. The installer adds Docker if it's missing (on Debian, Ubuntu and Alpine).
- A dedicated machine, not your laptop. OpenHut has root on it: it runs a Docker container for each agent.
- Ports **80** and **443** open to the internet. OpenHut gets its HTTPS certificate itself.
- A domain name, like `openhut.example.com`. Point its DNS (an `A` record) at the server **before** you install.

<Steps>
<Step>

### Run the installer

On the server:

```sh
curl -fsSL https://openhut.dev | sh
```

It downloads OpenHut, starts it and prints the address to open, like `http://203.0.113.7`.

</Step>
<Step>

### Open it right away

Open that address in your browser. The first person to open it becomes the owner, so do it as soon as the installer finishes. Enter your name, email and a password.

</Step>
<Step>

### Set the HTTPS address

Enter your domain, like `https://openhut.example.com`. OpenHut gets the certificate on ports 80 and 443 and moves you there. You can change it later in **Settings › Admin › Address**.

</Step>
<Step>

### Connect a model and make an agent

**Settings › Models**: sign in with your [Claude](/claude) or [ChatGPT](/codex) plan, or add an [API key](/api-keys). Then make your first [agent](/agents).

</Step>
</Steps>

Everyone else joins with an invite link from [People](/people).

## Hardware

Plan memory for the busiest moment: every running agent can use its full memory at once.

| Server | CPU | Memory | Disk |
| --- | --- | --- | --- |
| Try it: 2 agents, no browser | 2 vCPU | 4 GB | 20 GB |
| A team: 5 agents, 2 of them browse | 4 vCPU | 8 GB | 30 GB |
| A bigger team: 10 agents, 4 of them browse | 8 vCPU | 16 GB | 40 GB |

- **Memory:** 1 GB for OpenHut and the system, plus 1 GB for each running agent and 2 GB for each agent that browses the web.
- **CPU:** one core for OpenHut, plus one for each agent working at the same moment.
- **Disk:** 10 GB for the images and Docker, plus about 1 GB per agent.

Out of room? [Add another computer](/computers) and move agents to it.

## Behind an existing proxy

If the server already runs a reverse proxy on ports 80 and 443, install with `proxy` and the local port it should reach OpenHut on:

```sh
curl -fsSL https://openhut.dev | sh -s -- proxy 8787
```

OpenHut then listens only on `127.0.0.1:8787`, over plain HTTP. It leaves ports 80 and 443 alone and gets no certificate: your proxy serves HTTPS. Updates keep this setting. Point your domain's DNS at the server, add a route to your proxy, then open your HTTPS address and create the owner account. **Settings › Admin › Address** shows **HTTPS by your proxy**.

The proxy must send the original `Host` header. Plan memory as in [Hardware](#hardware), on top of what the server's other apps use: on a 4 GB server that already runs other apps, keep to one or two agents.

**nginx**, in a `server` block for your domain with its certificate:

```nginx
location / { proxy_pass http://127.0.0.1:8787; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection upgrade; proxy_read_timeout 1h; }
```

**Caddy**, which gets the certificate itself:

```text
openhut.example.com { reverse_proxy 127.0.0.1:8787 }
```

**kamal-proxy** runs in a container, so it can't reach the server's `127.0.0.1`. Add the Docker network it uses (Kamal's is `kamal`), and OpenHut joins it as `openhut`:

```sh
curl -fsSL https://openhut.dev | sh -s -- proxy 8787 kamal
docker exec kamal-proxy kamal-proxy deploy openhut --target openhut:8787 --host openhut.example.com --tls --health-check-path /health
```

Updates and rollbacks keep the container name `openhut` and the network, so the route keeps working.
