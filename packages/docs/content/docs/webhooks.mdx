A **webhook** is an address on your OpenHut that another service calls when something happens: an alert fires, a deploy finishes, a form is sent. Each call reaches the agent in a thread in the web app (or in the Discord channel you pick), and the agent does what its instructions say about it. Related calls, like an alert and its recovery, share one thread. See [Threads](/threads).

## Add one

Ask the agent:

```txt
Watch our DigitalOcean Postgres and tell #db-alerts when an alert fires.
```

It asks for a webhook, and a card shows up in the chat. **Approve** creates it. The agent learns the address, never the secret. It then posts a setup card with the steps for the service, the **Address** with **Copy** and the secret with **Copy secret**, both read from the webhook itself, so they're always right. Press **Done** once it's set up. In Discord it sends the steps and the address instead; copy the secret from OpenHut.

Or add one yourself: **More › Webhooks** on the agent's panel, type what calls it and **Add webhook**.

Each webhook shows:

- **Address**: paste it into the service that calls it.
- **Secret**: the service signs each call with it, or sends it as a token. **New secret** replaces it; calls signed with the old one stop working.
- **Runs in**: **Here in the web app** (the default), where you can reply in each call's thread, or one of the agent's channels, like a Discord channel. A thread that runs in Discord continues there; the web app shows it with **Open in Discord ↗**.
- **Threads**: **Keep related together** (the default) puts calls about the same thing in one thread, so an alert and its recovery read as one story. **New thread each call** suits forms, orders and signups. The agent picks one when it asks for the webhook, and you or the agent can change it later. In a Discord channel, the first call of a group starts a Discord thread and the agent answers later ones there.

## How calls are grouped

The first time a webhook is called, the agent looks at the payload and decides what makes calls belong together (for a DigitalOcean alert, the alert rule), how to title each thread and how to label each call. You don't set anything. A sender can also pick the thread itself with an `X-Group-Key` header: calls with the same value share a thread.

Delete a webhook with the trash icon. Calls to its address stop at once.

## DigitalOcean alerts

In DigitalOcean, open **Monitoring › Alerts** (Insights), add a webhook notification channel, paste the **Address**, turn on **Sign webhook payload** and paste the **Secret**. Then pick that channel on the alert rules for your database. DigitalOcean signs every call with `X-DigitalOcean-Signature`, and OpenHut checks it.

## Other services

OpenHut accepts any of these on each call:

- DigitalOcean's signature: `X-DigitalOcean-Signature: t=<time>,v1=<HMAC-SHA256 of "<time>.<body>">`, at most 5 minutes old.
- A GitHub-style signature: `X-Hub-Signature-256: sha256=<HMAC-SHA256 of the body>`.
- The secret itself as a token: `Authorization: Bearer <secret>` or `X-Webhook-Secret: <secret>`.

Calls without one get `401`.

## Limits

- A call's body can be up to 256 KB; bigger ones get `413`.
- A call the service sends again counts once, so a retry doesn't wake the agent twice. OpenHut knows a resend by its delivery id within 24 hours (`X-GitHub-Delivery`, `Idempotency-Key`, `webhook-id`, or an `id` at the top of the payload), or by the same body within 10 minutes when there's no id.
- Up to 120 calls in 15 minutes per webhook; more get `429`.
- The payload is data, not instructions: the agent reads it and follows its own instructions, not what the payload says.
- Keep the agent running. A call that comes while it's stopped reaches it once it starts; for the OpenHut app, only if that's within about 10 minutes.
