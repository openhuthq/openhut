### Connect one

**Settings › Apps**, then **Connect** next to the app. A short guide opens with the steps. An agent that needs apps asks for them in chat: its message lists each app with its own **Connect** (or **Add key**). That opens the app over the chat: use a connection you already have, or sign in (a new tab) or paste a key, and pick what the agent may do on its own for each kind of action. The agent gets access as soon as you connect, with no second step; the row ticks in place on every device, and the agent carries on once you've answered everything it asked for in that chat. **Tell it to do without it** declines.

Apps you sign in to open their sign-in in a new tab. You have 15 minutes to finish it, and it still finishes if OpenHut restarts meanwhile. Close the tab before you're done and OpenHut tells you, so you can sign in again.

Settings › Apps is one alphabetical list. Each connection has its own row, so an app connected twice shows twice, with a status that's the same everywhere: **Connected** (its last call worked), **Failing** (its last call failed) or **Not used yet**. Click a connected app's row to open its page.

An app's page shows its status, **Who can use it**, **What agents can do** and its activity. **What agents can do** lists each action by name. An app that runs everything through one catch-all tool hides its lookup tools and shows the actions agents have reached through it, by kind (look up, add, change, delete), with a count like *reaches 4 actions*. **Reconnect** signs in again for apps you signed in to, or asks for a new key or token for apps you connected with one. It stays the same connection, so who can use it and what agents may do in it don't change. When the app is failing, **Reconnect** is the main button.

### Hand it to an agent

On the agent, **Add** it under **Can use**. Or open the app and pick the agents under **Who can use it**.

## What you can connect

Each is an official MCP server, run with your own credentials:

- **GitHub:** one GitHub App per server. An admin sets it up once in **Settings › Admin › GitHub**: type the owner (your account or an organization you own), keep or change the name (like `acme-openhut`) and click **Continue on GitHub**. GitHub opens in a small window where you create the app and install it on your repositories; the OpenHut dialog follows along and ends on **Installed on N repositories**. From then on **Manage** shows the app, a link to add its avatar on GitHub, and **Remove**. After that, when an agent asks for GitHub you pick its repositories and what it may do (read code, open pull requests, merge); no sign-in, and its token reaches only those repositories. If the app isn't installed on the account yet, **Install on GitHub** installs it; if you aren't an owner there, GitHub sends the owner a request, the ask shows **Waiting for the owner** with **Copy link**, and OpenHut checks every minute for 7 days and connects it once they approve. Until an admin sets the app up, members see **Ask an admin**. Your key stays on your server: an agent's `git clone` and `git push` go through OpenHut, which adds the token on the way to GitHub, so it never lands in the agent's terminal or its git config. Each push and fetch shows in the agent's activity.
  Agents sign their work: a pull request, an issue and an agent's first comment in a thread end with one line, "Opened by Database, an AI agent · Made with OpenHut" (with its own name), with the agent's face. The line links only to openhut.dev, never to your server; inline review comments never get it. Agents also end their commits with an `OpenHut-Agent: Database` trailer.
- **Google:** Gmail (drafts only, no sending), Drive, Docs, Sheets, Slides, Calendar, Chat and Contacts. Needs a Google OAuth client, set once by an admin (below).
- **Linear** and **PostHog:** sign in.
- **Convex:** a deploy key.
- **Excalidraw:** no account. Agents draw a diagram and send a link to it; anyone with the link can open it.
- **Postgres:** read-only. Paste a connection string, or host, database, user and password. **Copy SQL** gives you the statements for a read-only role. OpenHut runs a test query when you save: if the database can't be reached, add this computer's IP to its trusted sources or firewall. A user that can change data still connects, with a warning to use a read-only one. Connection pools like PgBouncer work in any mode.
- **Custom MCP:** any MCP server by URL, with a header (like `Authorization`) or OAuth.

## Apps not on the list

An agent can also ask for an app that isn't on the list, like DigitalOcean, through the app's own MCP server: the row says which token to make, with a link to where you make it, and the agent never sees it. Once connected it shows in Settings › Apps under its own name and logo. If you decline, say why ("use the browser", "I'll set it up myself") and the agent follows it.

## Google OAuth client

In Google Cloud Console, create an OAuth client of type **Web application** and add the redirect URL OpenHut shows. Paste its client ID and secret when you first connect Google, or in **Settings › Admin › Sign in with Google**. One client serves Google sign-in and the Google apps.

Keys stay on your main install, sealed. Agents call apps through OpenHut and never see them. What each agent may do in an app on its own, and what it asks you first, is under [Permissions](/permissions).
