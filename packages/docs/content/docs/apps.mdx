### Connect one

**Settings › Apps**, then **Connect** next to the app. A short guide opens with the steps. An agent that needs apps asks for them in chat: its message lists each app with its own **Connect** (or **Add key**). That opens the app over the chat: use a connection you already have, or sign in (a new tab) or paste a key, and pick what the agent may do on its own for each kind of action. The agent gets access as soon as you connect, with no second step; the row ticks in place on every device, and the agent carries on once you've answered everything it asked for in that chat. **Tell it to do without it** declines.

Apps you sign in to open their sign-in in a new tab. You have 15 minutes to finish it, and it still finishes if OpenHut restarts meanwhile. Close the tab before you're done and OpenHut tells you, so you can sign in again.

Settings › Apps is one alphabetical list. Each connection has its own row, so an app connected twice shows twice, with a status that's the same everywhere. A working app says **Connected**. One failed call doesn't change that: agents deal with the odd error themselves. An app shows a problem only when it needs you: **Signed out** (its sign-in expired), **Login rejected** (the app turned down its key or password) or **Not working** (its last three calls failed within a day). Click a connected app's row to open its page.

An app's page shows a problem, if there is one, with **Reconnect** beside it, then **Who can use it** and **What agents can do**. Ticking or unticking an agent takes effect at once, without restarting it; **Permissions** beside a ticked agent opens what that agent may do in the app. **What agents can do** lists each action by name, grouped by kind (look things up, add, change, delete). An app that runs everything through one catch-all tool hides its lookup tools and shows the actions agents have reached through it, with a count like *reaches 4 actions*. **Reconnect** is on every app: it signs in again for apps you signed in to, asks for a new key or token for apps you connected with one, and checks the install again for GitHub. It stays the same connection, so who can use it and what agents may do in it don't change.

## What you can connect

Each is an official MCP server, run with your own credentials:

- **GitHub:** one GitHub App per server. An admin sets it up once, in **Settings › Admin › GitHub** or by pressing **Connect** on GitHub (in Settings › Apps or on an agent's ask), which opens the same setup and goes straight on to connecting once it's done: pick the owner (the list suggests owners you used before and their public organizations; for a private organization, type its name), keep or change the name (like `acme-openhut`) and click **Continue on GitHub**. GitHub opens in a small window where you create the app and install it on your repositories; the OpenHut dialog follows along and ends on **Installed on N repositories**. From then on **Manage** shows the app, a link to add its avatar on GitHub, and **Remove**. After that, when an agent asks for GitHub you pick its repositories and what it may do (read code, open pull requests, merge); no sign-in, and its token reaches only those repositories. If the app isn't installed on the account yet, **Install on GitHub** installs it; if you aren't an owner there, GitHub sends the owner a request, the ask shows **Waiting for the owner** with **Copy link**, and OpenHut checks every minute for 7 days and connects it once they approve. Until an admin sets the app up, members who press **Connect** see **Ask an admin**. Your key stays on your server: an agent's `git clone` and `git push` go through OpenHut, which adds the token on the way to GitHub, so it never lands in the agent's terminal or its git config. Each push and fetch shows in the agent's activity. Git has two permissions under GitHub: **Read code**, Always allow to start, and **Push branches**, Ask first to start (it sits with **Open pull requests**, so what you pick there applies). With Ask first the agent asks before it pushes, and the card names the repository and branch, like *Push to GitHub · acme/api (fix-docs)* with the GitHub logo: **Always allow** lets it push without asking, **Allow** lets it push there for the next 10 minutes. A push set to Never shows in the chat with **Change permission**, which opens GitHub's permissions on that entry.
  Agents sign their work: a pull request, an issue and an agent's first comment in a thread end with one line, "Opened by Database, an AI agent" (with its own name), with the agent's face. The line has no links; inline review comments never get it. Agents also end their commits with an `OpenHut-Agent: Database` trailer.
- **Google:** Gmail (drafts only, no sending), Drive, Docs, Sheets, Slides, Calendar, Chat and Contacts. Needs a Google OAuth client, set once by an admin (below).
- **Linear** and **PostHog:** sign in.
- **Convex:** a deploy key.
- **Excalidraw:** no account. Agents draw a diagram and send a link to it; anyone with the link can open it.
- **Postgres:** read-only. Paste a connection string, or host, database, user and password. **Copy SQL** gives you the statements for a read-only role. OpenHut runs a test query when you save: if the database can't be reached, add this computer's IP to its trusted sources or firewall. A user that can change data still connects, with a warning to use a read-only one. Connection pools like PgBouncer work in any mode.
- **ClickHouse:** read-only. Enter the address (like `https://abc.clickhouse.cloud:8443`), a user, a password and an optional database, or paste one connection string like `https://reader:password@host:8443/default`. **Copy SQL** gives you the statements for a user that can only read. OpenHut runs a test query when you save. Agents can list databases and tables, describe a table and run one SELECT at a time: every query runs in ClickHouse's read-only mode, stops after 15 seconds and returns at most 1000 rows.
- **Better Stack:** search your logs in Better Stack Telemetry. Paste a Telemetry API token, from **API tokens › Team-based tokens** in Better Stack; OpenHut checks it when you save. Agents can list sources, search a source for log lines that contain some text in a time range (the last hour unless they say otherwise), and run one read-only SQL query over a source, 1000 rows at most. The token only reads; nothing changes in Better Stack.
- **Custom MCP:** any MCP server by URL, with a header (like `Authorization`) or OAuth.

## Apps not on the list

An agent can also ask for an app that isn't on the list, like DigitalOcean, through the app's own MCP server: the row says which token to make, with a link to where you make it, and the agent never sees it. Once connected it shows in Settings › Apps under its own name and logo. If you decline, say why ("use the browser", "I'll set it up myself") and the agent follows it.

## Google OAuth client

In Google Cloud Console, create an OAuth client of type **Web application** and add the redirect URL OpenHut shows. Paste its client ID and secret when you first connect Google, or in **Settings › Admin › Sign in with Google**. One client serves Google sign-in and the Google apps.

Keys stay on your main install, sealed. Agents call apps through OpenHut and never see them. What each agent may do in an app on its own, and what it asks you first, is under [Permissions](/permissions).
