### Connect one

**Settings › Apps**, then **Connect** next to the app. A short guide opens with the steps. An agent that needs apps asks for them in chat: one card lists each app with its own **Connect**, which opens the same guide.

Settings › Apps is one alphabetical list. Each connection has its own row, so an app connected twice shows twice, with a status that's the same everywhere: **Connected** (its last call worked), **Failing** (its last call failed) or **Not used yet**. Click the status to open the app.

</Step>
<Step>

### Hand it to an agent

On the agent, **Add** it under **Can use**. Or open the app and pick the agents under **Who can use it**.

</Step>

## What you can connect

Each is an official MCP server, run with your own credentials:

- **GitHub:** a GitHub App of your own. You approve it twice; agents commit as its bot. Your key stays on your server: an agent's `git clone` and `git push` go through OpenHut, which adds the token on the way to GitHub, so it never lands in the agent's terminal or its git config. Each push and fetch shows in the agent's activity.
  Agents sign their work: a pull request, an issue and an agent's first comment in a thread end with one line, "Opened by <agent>, an AI agent · Made with OpenHut", with the agent's face. The line links only to openhut.dev, never to your server; inline review comments never get it. Agents also end their commits with an `OpenHut-Agent: <name>` trailer.
- **Google:** Gmail (drafts only, no sending), Drive, Docs, Sheets, Slides, Calendar, Chat and Contacts. Needs a Google OAuth client, set once by an admin (below).
- **Linear** and **PostHog:** sign in.
- **Convex:** a deploy key.
- **Excalidraw:** no account. Agents draw a diagram and send a link to it; anyone with the link can open it.
- **Postgres:** read-only. Paste a connection string, or host, database, user and password. **Copy SQL** gives you the statements for a read-only role.
- **Custom MCP:** any MCP server by URL, with a header (like `Authorization`) or OAuth.

## Apps not on the list

An agent can propose an app that isn't on the list, like DigitalOcean, through the app's own MCP server. The card says what the agent may do there (**Always allow**, **Ask first** or **Never** for each kind of action), and you can change each before you agree. **Connect** asks for the app's token, with a link to where you make it; the agent never sees it. Once connected it shows in Settings › Apps under its own name and logo. Or choose **Do it once with the browser**, or **I'll set it up myself** and the agent tells you how.

## Google OAuth client

In Google Cloud Console, create an OAuth client of type **Web application** and add the redirect URL OpenHut shows. Paste its client ID and secret when you first connect Google, or in **Settings › Admin › Sign in with Google**. One client serves Google sign-in and the Google apps.

Keys stay on your main install, sealed. Agents call apps through OpenHut and never see them. What each agent may do in an app on its own, and what it asks you first, is under [Permissions](/permissions).
