title: Multiple agents
description: One agent per job. Give it a name, a job, and what it can reach.
icon: ops
---

<Shot src="agent" alt="An agent's page: instructions, status, channels, connections and skills" />

<Steps>
<Step>

### Name it

**Agents**, then **New agent**. Its page opens with the name selected: type one after its job, like Support, Sales or Dev. Double-click the name to change it later.

</Step>
<Step>

### Tell it its job

Write its **Instructions** the way you'd brief a new teammate. Two sentences are enough.

</Step>
<Step>

### Give it a channel and data

Set up [Slack](/slack), [WhatsApp](/whatsapp) or [Telegram](/telegram), and add the [data](/data) it needs.

</Step>
<Step>

### Start it

Press **Start**. **Stop** pauses it and keeps what it learned.

Each agent can run code in its sandbox. Switch **Code execution** off on its page for an agent that shouldn't.

An agent can also use a real web browser. **Browser** is off until you switch it on; the agent restarts once. The browser runs inside the agent's own sandbox and reaches the public web over HTTPS only. While Browser is on, the agent can use up to 4 GB of memory, whatever its Computer size.

With Browser on, the agent's page shows a small picture of what its browser has open, refreshed every few seconds while you look. **Watch live** opens it full screen in a new tab. Press **Take over** to click and type yourself, for example to log in to a site or get past a check; the agent can't act until you press **Hand back**, or after 2 minutes without input. Only people who can edit the agent can watch or take over.

Logins stay in the agent's browser between conversations. The agent can read its own browser, so log it in with an account made for it, not your personal one. A web page can carry text written to mislead an agent, so switch Browser on only for agents that need it.

</Step>
</Steps>
