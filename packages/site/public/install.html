Install OpenHut

One command on your own Linux server. OpenHut is self-hosted and free: you bring the server, the domain and the keys.

Requirements

  • A Linux server or VM with Docker. Any distribution, x86_64 or arm64. See Hardware for how big.
  • A domain with HTTPS pointing at it, for example openhut.example.com. See HTTPS.
  • A dedicated server or VM, not your laptop. The install has root on the host: it runs Docker containers for your agents with gVisor when the machine supports it.

Install

On the server, run:

curl -fsSL https://openhut.dev | sh

It pulls the OpenHut image and its runtime, starts them, and prints a setup link with a one-time code:

OpenHut is running.

  Open this link to create your account:

    https://openhut.example.com/setup?code=K7PQ-4M2X

  Or open https://openhut.example.com/setup and paste the setup code: K7PQ-4M2X
  The code works once. Whoever uses it first becomes the owner.

  OpenHut listens on 127.0.0.1:8787. Point your HTTPS proxy (Caddy, nginx, Cloudflare Tunnel) at it.

Open the link, enter your email and a password. That account is the owner; everyone else joins by an invite link from Settings › People.

HTTPS

OpenHut listens only on 127.0.0.1:8787, plain HTTP. Put one HTTPS proxy in front of it. Three ways, pick one.

Caddy

Caddy gets the certificate for you. As a one-liner:

caddy reverse-proxy --from openhut.example.com --to 127.0.0.1:8787

Or in /etc/caddy/Caddyfile:

openhut.example.com {
	reverse_proxy 127.0.0.1:8787
}

nginx

With a certificate from certbot or your own:

server {
    listen 443 ssl;
    server_name openhut.example.com;
    ssl_certificate     /etc/letsencrypt/live/openhut.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/openhut.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 1h;
    }
}

Tailscale

For a team on one tailnet, with no public domain:

tailscale serve --bg 8787

OpenHut is then at https://<machine>.<tailnet>.ts.net for everyone on your tailnet.

Hardware

Plan memory for the busiest moment: every running agent can use its full memory at once.

ServerCPUMemoryDisk
Try it: 2 agents, no browser2 vCPU4 GB20 GB
A team: 5 agents, 2 of them browse4 vCPU8 GB30 GB
A bigger team: 10 agents, 4 of them browse8 vCPU16 GB40 GB

To size your own:

  • Memory: 1 GB for OpenHut and the system, plus 1 GB for each running agent and 2 GB for each agent that browses the web. An idle agent uses about 400 MB.
  • CPU: one core for OpenHut, plus one for each agent working at the same moment. Opening a web page takes a full core for a second or two.
  • Disk: 10 GB for the images and Docker, plus about 1 GB per agent for its memory, files and browser profile.

Out of room? Add another machine and move agents to it.

Add another machine

In OpenHut, open Settings › Computers › Add a computer. It shows one command with a token in it; run it on the new machine within 10 minutes. The machine needs Docker, like the first one.

curl -fsSL https://openhut.dev | sh -s -- join https://openhut.example.com <token>

That machine runs only the runtime: it runs agents and connects to your main install, which keeps the app, the accounts and the model keys. It needs no domain or HTTPS of its own. Move an agent to it from the agent's Runs on.

Update

Open Settings › Updates and click Update now. The main install updates first and the other machines follow it to the same version. If the new version doesn't start, OpenHut goes back to the previous one.

Uninstall

curl -fsSL https://openhut.dev | sh -s -- uninstall

Run it on each machine. It asks you to type uninstall first, then deletes every agent and all OpenHut data on that machine. This cannot be undone. Docker and everything else stay.

Bring your own keys

OpenHut runs no services for you. Each one is yours, added in the app, and the keys stay on your main install. Agents never see them.

  • Models: sign in with your Claude or ChatGPT plan, or paste an API key from Anthropic, OpenAI, OpenRouter or any OpenAI-compatible address. Set it when you create an agent or in Settings › Models.
  • Google (Gmail, Drive, Calendar): create your own OAuth client in Google Cloud Console and paste its client ID and secret when you connect Google. The sheet in the app lists the redirect URL to add.
  • Telegram: make a bot with @BotFather and paste its token on the agent's Telegram channel.

Slack and WhatsApp work the same way: each agent gets its own Slack app or WhatsApp number, set up from the agent's channels.
