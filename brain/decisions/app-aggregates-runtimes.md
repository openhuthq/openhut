# The app aggregates runtimes

## Decision
Owner, 2026-11-17 (design, version 2: https://claude.ai/artifact/Cpd6WVPjfBB49ASU5dUSiD). Every computer runs a **runtime**: today's server and agentd, shipped as one package (`packages/runtime`, `src/server` and `src/agentd`, still two processes), with its own database, agents, connections, sealed keys, gateway, broker and scheduler. The Mac runs one; each computer you add runs one. The desktop app is a thin window over all of them and keeps only what belongs to you: your computers and the key for each, subscriptions to push, preferences.
- **Local runtime**: the app starts it with `OPENHUT_SOCKET`; every request on the 0600 socket is the owner (the local-socket half of `auth-is-local-socket-or-tailscale.md`).
- **Remote runtime**: installed by curl with `OPENHUT_CLIENT_KEY_SHA256`, the hex SHA-256 of a random 32-byte key the app makes when you add the computer (hashed as the string the app sends). The server refuses to start in remote mode without it. It listens on 127.0.0.1:8787 and the tailnet reaches it through `tailscale serve --bg --https=443 http://127.0.0.1:8787`. A request is the owner only with `Authorization: Bearer <key>` whose SHA-256 matches, compared with `timingSafeEqual`. The control MCP takes the same header.
- No people, roles, invites, Tailscale-User-Login identity or Public URL. One implicit owner row stays so `owner_id` columns keep working.
- Nothing needs a public address: channels are outbound (Slack Socket Mode, Telegram polling through the broker, WhatsApp's bridge), and connection sign-ins return to the runtime's tailnet URL (set by the app at enrollment), or on the Mac to `127.0.0.1`, which the app turns into `app://openhut`. A runtime with a tailnet URL has no dashboard, so its callback answers a plain page ("Connected. You can close this tab and go back to OpenHut.", or the error) and the app sees the new connection on its next poll. Public inbound (webhook triggers) waits for the managed-cloud relay.
- **Codex is coming soon** (owner, 2026-11-17). Only the Claude sign-in is live: the app pushes only Claude between computers, and a runtime answers 409 "Codex is coming soon." to setting an agent's model to `codex` or importing one that has it. The `codex` model id, `Admin.codex`, the ChatGPT sign-in endpoints and the codex transfer stay, dormant, so existing rows still parse and turning it on is adding `'codex'` back to the client's `SUBSCRIPTIONS` and dropping the two checks.
- **Moving an agent** (`openhut.agents.move({ id, to })`): the app stops it on the source, asks the target for its `publicKey`, takes `POST /api/agents/:id/export` from the source (refused while its VM runs), hands the sealed bundle to `POST /api/agents/imports` on the target, starts it there if it was running, and only then deletes it on the source. If anything before that fails it deletes the half-made copy on the target and starts the agent again on the source. The bundle is sealed to the target like a connection export and holds the agent row (same id; a new `net`, channel key and token on the target), its channels with their tokens (Slack, Telegram) and statuses, its chats, the kind and name of each connection it held, and its whole home as a gzipped tar from agentd's `home-export` (memories, skills, Hermes' `state.db`, the WhatsApp session under `platforms/`). Grants come back for connections the target has with the same kind and name; the rest come back as `ungranted` names for the app to show. The packed home is capped at 100 MB; past that the move stops and the agent restarts where it was.
- **MCP is per computer** (owner, 2026-11-17). Each runtime keeps its own `/mcp` and tools. You add one server per computer to your AI: `claude mcp add openhut -- <bridge>` talks to the Mac's runtime socket; `claude mcp add openhut-<name> -- <bridge> --computer <id>` talks to the app's `mcp.sock` (0600, in its user data), which forwards only `/c/<id>/mcp` with that computer's key, so the key never leaves the app. Without the app running, only the Mac's server works. The app lists the commands over IPC `mcp.commands`.
- The app's main process uses `packages/client` too (bundled to `client.mjs` in the package), so the tray and notifications cover every computer; an offline computer's agents show greyed.

## Context
Version 1 put one server on the Mac and pushed desired state and sealed keys to runtimes on other computers. A runtime that owns everything needs no sync, keeps working while the Mac sleeps, and loses nothing when the Mac does.

## Why
- The runtime is the server we have, nearly unchanged; the new pieces are a second transport and one key check.
- A key the app holds says exactly "this app", which a tailnet login never did: anyone on the tailnet could reach `tailscale serve`.
- One package is one thing to build, ship and update; on a server agentd stays the root helper and the server stays unprivileged.

## Consequences
- Supersedes the server-mode half of `auth-is-local-socket-or-tailscale.md` (Tailscale-User-Login, first login owns, people) and version 1's desired-state sync.
- `/api/people`, the `add_person`, `list_people` and `delete_person` tools, `Me.publicUrl`, `Admin.publicUrl`, webhook automations (`/hooks/:id`) and `/api/admin/containers` are gone; `Admin.tailnetUrl` is new. Rows a removed teammate owned move to the owner on migrate.
- The curl install on a bare host runs in the `openhut` container, which publishes 8787 on the host's 127.0.0.1 only; inside it the runtime binds 0.0.0.0 (`OPENHUT_HOST`), so the host's Docker bridge can reach it, answered only with the key. Containers made before this have no published port.
- Adding a computer that already runs the build being served pairs instead of reinstalling (owner, 2026-11-17: "if it's installed you should be able to add it"): the installer writes the new key hash to `/etc/openhut/env`, restarts only the server (`openhut.service`, or `host-start.sh` without systemd) and waits for it, then sets `tailscale serve`. An older build upgrades as before. Either way the new key replaces the old one and the installer says so; the app that added it before loses access. The installer waits up to 3 minutes for another install's lock. The app replaces a computer with the same address in its list, keeping its id.
- An install without a key (an old install upgraded by curl, or by hand) stops before it changes anything until the app enrolls one.
- Telemetry never sends an email: the owner is only a Unix username now.
- An agent's home is extracted by agentd as root on a server (GNU tar refuses `..` members and defers symlinks; bsdtar on the Mac refuses both); the bundle only ever comes from the owner's own computer.
- Still to build: the dashboard's "Move to…" menu, and checking the app's `mcp.sock` and tray against a real remote computer.
